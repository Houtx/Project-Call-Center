# 外呼录音说明

## 工作方式

管理员在“坐席与设备 > 坐席账号”中独立开启某个坐席的录音开关。开关只影响之后新创建的外呼尝试，已经开始的外呼不会被追溯改变。APP 的任务、拨号和通话记录界面不显示录音开关，录音采集只由服务端在外呼授权响应中下发。

设备完成通话后，APP 将本地私有目录中的压缩 AAC/M4A 文件上传到服务端。服务端按照坐席、设备和 `attemptId` 校验归属，使用独立的 `RECORDING_ENCRYPTION_KEY` 进行 AES-256-GCM 静态加密后，存放在不可被 Nginx 直接访问的录音卷中。管理员播放、下载都会经过登录鉴权、即时解密并写入审计日志；数据库保留状态、大小、摘要、时间和失败原因，不保存音频正文。

默认录音编码为 16 kHz、单声道、AAC 24 kbps，服务端单文件上限 25 MB。管理员可以在“APP 与外呼策略”中设置录音保留天数（1-365 天）。服务端后台任务每小时分批清理超过期限的音频文件，并把记录标为“已清理”，通话结果和审计元数据继续保留。文件删除失败时不会提前标记完成，下一轮会继续重试。

## Android 能力边界

普通 Android 应用无法在所有 Android 12+ 手机上读取系统拨号器的蜂窝通话双向音频。只有经过企业/OEM 授权、允许 `MediaRecorder.AudioSource.VOICE_CALL` 的设备才可能得到双方录音。系统拒绝音频源、撤销麦克风权限或设备策略不允许时，APP 会回传“设备不支持”，后台不会显示一条伪造的录音。

Android 会显示系统麦克风隐私指示，这是操作系统强制的隐私行为，不能通过应用隐藏。上线前必须按品牌、型号、系统版本和默认电话应用逐一真机验收；不满足双方音频采集、通话时长和断网补传要求的组合不得开启坐席录音。

## 合规与运维

开启录音前，管理员应确认员工和客户所在地对通话录音、告知同意、个人信息处理和保存期限的要求。录音卷应使用独立磁盘/对象存储、限制容器权限、纳入备份和恢复演练，并监控剩余空间。删除录音只删除音频文件，审计日志保留谁开启、谁播放、谁下载和何时清理等操作记录。
